# Compiler Target Architecture: Option A Specification

## Executive Summary

This document specifies a proposed architectural change to the Composable Rust framework's compilation target. The change separates **business logic** from **infrastructure orchestration**, resulting in cleaner generated code, smaller event stores, and easier debugging.

**Current State**: Single monolithic reducer per aggregate (~2,300 lines) mixing business domain logic with infrastructure concerns (state loading, version tracking, serialization).

**Proposed State (Option A)**: Two-layer architecture per aggregate:
1. **Business Reducer** (~300-500 lines): Pure domain logic, validation, state transitions
2. **Infrastructure Handler** (~500-800 lines): Orchestration, persistence, serialization (nearly identical across all aggregates)

**Primary Benefit**: The event store becomes a clean audit log of business decisions, free from infrastructure noise.

## Context and Motivation

### The Vision

The Composable Rust framework serves as a **compilation target** for a higher-level YAML-based language. The workflow is:

```
Natural Language Specification
         │
         ▼ (AI generates)
    YAML Specification
         │
         ▼ (Compiler generates)
     Rust Code (this framework)
         │
         ▼ (cargo build)
    Production Binary
```

Users never write or read the generated Rust code. They work entirely in YAML, which is generated by AI from natural language specifications.

### The Question

Given that generated code is never human-authored, what makes the **best compilation target**?

1. **Ease of generation**: Is the compiler simpler to write?
2. **Operational excellence**: Is the generated system easier to debug and operate?
3. **Performance**: Is the generated code efficient?
4. **Safety**: Does the architecture prevent bugs at compile time?

### Key Insight

The current architecture optimizes for **human readability**—everything in one place, explicit action flow. But for a compilation target, we should optimize for:

- **Separation of concerns**: Business logic isolated from infrastructure
- **Clean event stores**: Only business events persisted
- **Debuggability**: Quickly identify business logic issues vs infrastructure issues
- **Template-based generation**: Infrastructure code is identical across aggregates

## Current Architecture Analysis

### Structure

Each aggregate is a single file containing:

```rust
// State
pub struct EventState { ... }

// Actions (mixed concerns)
pub enum EventAction {
    // === Commands (from API) ===
    CreateEvent { ... },
    UpdateEvent { ... },

    // === Business Events ===
    EventCreated { ... },
    EventUpdated { ... },

    // === Infrastructure Actions (the problem) ===
    LoadExistingState { stream_id, respond_to },
    StateLoaded { state, version },
    ExecuteCreateEvent { respond_to, ... },
    ExecuteUpdateEvent { respond_to, ... },
    LoadFailed { error },
    VersionUpdated { version },
    ValidationFailed { error },
    SerializationFailed { error },
}

// Environment
pub struct EventEnvironment { ... }

// Reducer (800+ lines)
impl Reducer for EventReducer {
    fn reduce(&self, state: &mut State, action: Action, env: &Env) -> Effects {
        match action {
            // Two-phase async pattern
            CreateEvent { .. } => {
                // Emit LoadExistingState effect
            }
            StateLoaded { state, version } => {
                // Emit ExecuteCreateEvent effect
            }
            ExecuteCreateEvent { .. } => {
                // Validate, emit EventCreated, persist
            }
            EventCreated { .. } => {
                // Apply to state (replay)
            }
            VersionUpdated { version } => {
                // Update internal version tracking
            }
            // ... 30+ more variants
        }
    }
}
```

### Problems Identified

#### 1. Action Enum Bloat with Infrastructure Variants

The `EventAction` enum has **32 variants**, but only ~10 are business commands/events. The remaining ~22 are infrastructure actions that exist solely to support the two-phase async pattern:

- `LoadExistingState`, `StateLoaded`, `LoadFailed` - state loading choreography
- `ExecuteCreateEvent`, `ExecuteUpdateEvent`, etc. - deferred execution
- `VersionUpdated` - version tracking (in-memory only, not persisted)
- `ValidationFailed`, `SerializationFailed` - error handling

Every command follows this multi-hop pattern:

```
Command → LoadExistingState → StateLoaded → Execute* → BusinessEvent → VersionUpdated
```

The `Execute*` variants exist solely because reducers can't do I/O. They're infrastructure artifacts, not business concepts. While these infrastructure actions don't get persisted to the event store, they bloat the action enum and make it harder to understand what the aggregate actually does from a business perspective.

#### 2. `respond_to` Field Smell

Commands and internal actions contain infrastructure concerns:

```rust
// Command has infrastructure concern
CreateEvent {
    event_id: EventId,
    name: String,
    venue: Venue,
    respond_to: ResponseChannel,  // Infrastructure leak!
}

// Execute* actions carry it through the async flow
ExecuteCreateEvent {
    event_id: EventId,
    name: String,
    venue: Venue,
    respond_to: ResponseChannel,  // Passed through multiple hops
}
```

The `respond_to` field enables request-response correlation but pollutes the domain model. Every command must carry this infrastructure concern, and it gets copied through multiple action variants during the two-phase async flow.

#### 3. Verbose Generated Code

Each aggregate is ~2,300 lines. For a compilation target, this means:
- Larger binary sizes
- More code to debug when issues arise
- More surface area for generation bugs

### What Works Well

Despite the problems, the current architecture:
- Is **correct** and production-ready
- Has **full test coverage**
- Handles **complex scenarios** (sagas, compensation, parallel operations)
- Uses **broadcast_on_success** pattern correctly (fixed recently)

## Option A: Separated Architecture

### Core Concept

Split each aggregate into two distinct components:

```
┌─────────────────────────────────────────────────────────────┐
│  Infrastructure Handler (generated, nearly identical)       │
│  ┌─────────────────────────────────────────────────────────┐│
│  │ 1. Load current state from event store                  ││
│  │ 2. Delegate to business reducer                         ││
│  │ 3. Persist resulting events                             ││
│  │ 4. Broadcast for projections/sagas                      ││
│  └─────────────────────────────────────────────────────────┘│
│                           │                                 │
│                           ▼                                 │
│  ┌─────────────────────────────────────────────────────────┐│
│  │  Business Reducer (generated, domain-specific)          ││
│  │                                                         ││
│  │  CreateEvent → validate → Ok(EventCreated)              ││
│  │  PublishEvent → validate → Ok(EventPublished)           ││
│  │  CancelEvent → validate → Ok(EventCancelled)            ││
│  └─────────────────────────────────────────────────────────┘│
└─────────────────────────────────────────────────────────────┘
```

### Key Principles

1. **Business logic is pure**: No I/O, no effects, just `(State, Input) → Result<BusinessResult, Error>`
2. **Infrastructure handler orchestrates**: Loads state, calls business logic, persists, broadcasts
3. **Event store is clean**: Only business events persisted
4. **Infrastructure is templated**: 90% identical across all aggregates
5. **Unified model**: Aggregates and sagas use the **same traits and handler**—sagas are just aggregates that call other aggregates

### Unified Framework Philosophy

A critical design principle: **sagas and aggregates use the same framework**. They share:

- The same `BusinessLogic` trait
- The same `Handler` implementation
- The same execution loop

The only difference is what the business logic *returns*:

```rust
/// Unified result type for business logic
///
/// - `E`: Event type (domain events to persist)
/// - `C`: Call type (aggregate calls for sagas; `Infallible` for aggregates)
pub enum BusinessResult<E, C> {
    /// Emit events and finish processing
    ///
    /// Aggregates always use this. Sagas use this for their final step
    /// (either successful completion or terminal failure).
    Done(Vec<E>),

    /// Emit events, call other aggregates, then continue processing their feedback
    ///
    /// Only sagas use this—aggregates never call other aggregates.
    /// The handler will execute the calls, collect results, and feed them
    /// back to the saga via `feedback_input()`.
    Continue {
        events: Vec<E>,
        calls: Vec<C>,
    },
}
```

**Design Decision: Errors vs Results**

All rejections (validation failures, invalid state transitions) return `Err(Self::Error)`. There is no `Reject` variant. This keeps the model simple:

- `Ok(Done(events))` → Success, persist events, finish
- `Ok(Continue { events, calls })` → Success so far, persist events, execute calls, continue
- `Err(error)` → Failure, persist nothing, return error to caller

This means:
- **Aggregates** always return `Ok(Done(events))` or `Err(error)`
- **Sagas** return `Ok(Continue { ... })` when orchestrating, `Ok(Done(events))` when finished, or `Err(error)` on failure

One handler handles both:

```rust
impl<T, E> Handler<T, E>
where
    T: BusinessLogic,
    E: CallExecutor<T::Call, T::CallResult>,
{
    async fn handle(&self, input: T::Input) -> Result<HandleResult, HandlerError<T::Error>> {
        let stream_id = T::stream_id(&input);
        let (mut state, mut version) = self.load_state(&stream_id).await?;
        let mut current_input = input;

        loop {
            let result = self.business
                .process(&state, current_input, self.clock.as_ref())
                .map_err(HandlerError::Business)?;

            match result {
                BusinessResult::Done(events) => {
                    if !events.is_empty() {
                        version = self.persist_events(&stream_id, &events, version).await?;
                        self.apply_all(&mut state, &events);
                        self.broadcast(&events).await?;
                    }
                    return Ok(HandleResult { version });
                }

                BusinessResult::Continue { events, calls } => {
                    if !events.is_empty() {
                        version = self.persist_events(&stream_id, &events, version).await?;
                        self.apply_all(&mut state, &events);
                        self.broadcast(&events).await?;
                    }

                    // Execute aggregate calls and feed results back
                    let feedback = self.call_executor.execute(calls).await;
                    current_input = T::feedback_input(feedback);
                    // Loop continues with feedback...
                }
            }
        }
    }
}
```

For aggregates, the loop always exits on the first iteration (they always return `Done`).
For sagas, the loop continues until the saga returns `Done` (completion or failure).

### Benefits

| Benefit | Description |
|---------|-------------|
| **Clean event store** | Only `EventCreated`, `EventPublished`, etc.—no `VersionUpdated` noise |
| **Smaller business logic** | ~300-500 lines vs ~2,300 lines |
| **Easier debugging** | Business logic isolated; check it first, then infrastructure if needed |
| **Template-based infra** | Infrastructure handler is nearly identical across all aggregates and sagas |
| **Compile-time safety** | Business code can't accidentally use infrastructure types |
| **Smaller types** | Business: ~10 variants. No infrastructure actions in the enum at all |
| **Unified model** | One `BusinessLogic` trait, one `Handler`—sagas and aggregates share the same framework |
| **Industrial-grade compensation** | Sagas have explicit compensation with rollback guarantees |
| **Simple error model** | `Ok` = persist events, `Err` = persist nothing. No ambiguity |

## Aggregate Implementation

### Business Reducer

```rust
// ═══════════════════════════════════════════════════════════════════
// GENERATED: Business Types (maps directly to YAML)
// ═══════════════════════════════════════════════════════════════════

/// Business commands (input)
pub enum EventCommand {

        owner_id: UserId,

        date: EventDate,
        pricing_tiers: Vec<PricingTier>,
    },
    Update {

    },
    Publish {
        event_id: EventId,
    },

        event_id: EventId,

    },
}

/// Business events (output, persisted)
pub enum EventEvent {
    Created {
        event_id: EventId,
        name: String,
        owner_id: UserId,
        venue: Venue,
        date: EventDate,
        pricing_tiers: Vec<PricingTier>,
        created_at: DateTime<Utc>,
    },
    Updated {
        event_id: EventId,
        changes: EventChanges,
        updated_at: DateTime<Utc>,
    },
    Published {
        event_id: EventId,
        published_at: DateTime<Utc>,
    },
    Cancelled {
        event_id: EventId,
        reason: String,
        cancelled_at: DateTime<Utc>,
    },
}

/// Business errors
pub enum EventError {
    AlreadyExists,
    NotFound,
    InvalidStateTransition { from: EventStatus, to: EventStatus },
    ValidationFailed { message: String },
}

/// Domain state
pub struct EventState {
    pub event_id: Option<EventId>,
    pub name: String,
    pub owner_id: Option<UserId>,
    pub venue: Option<Venue>,
    pub date: Option<EventDate>,
    pub status: EventStatus,
    pub pricing_tiers: Vec<PricingTier>,
}

// ═══════════════════════════════════════════════════════════════════
// FRAMEWORK: Unified BusinessLogic trait (same for aggregates and sagas)
// ═══════════════════════════════════════════════════════════════════

/// The unified trait for all business logic—aggregates and sagas alike.
///
/// This trait abstracts over both aggregates and sagas:
/// - Aggregates: `Call = Infallible`, `CallResult = Infallible` (never used)
/// - Sagas: `Call = SagaAggregateCall`, `CallResult = SagaAggregateResult`
///
/// The framework doesn't know or care which one it's running—the types
/// encode the distinction.
pub trait BusinessLogic: Send + Sync + 'static {
    /// Domain state, reconstructed by replaying events
    type State: Default + Send + Sync;

    /// Input to process (command for aggregates, command-or-feedback for sagas)
    type Input: Send;

    /// Domain events to persist
    type Event: Serialize + DeserializeOwned + Send + Sync + Clone;

    /// Business errors (validation failures, invalid state transitions)
    type Error: std::error::Error + Send + Sync;

    /// Aggregate calls (saga only). Use `std::convert::Infallible` for aggregates.
    type Call: Send;

    /// Results from aggregate calls (saga only). Use `std::convert::Infallible` for aggregates.
    type CallResult: Send;

    /// Extract stream ID from input (for loading/persisting events)
    fn stream_id(input: &Self::Input) -> StreamId;

    /// Process input (command or feedback) and return what to do next
    ///
    /// Returns:
    /// - `Ok(Done(events))` → Persist events and finish
    /// - `Ok(Continue { events, calls })` → Persist events, execute calls, continue
    /// - `Err(error)` → Fail without persisting anything
    fn process(
        &self,
        state: &Self::State,
        input: Self::Input,
        clock: &dyn Clock,
    ) -> Result<BusinessResult<Self::Event, Self::Call>, Self::Error>;

    /// Apply an event to state (for replay/reconstruction)
    ///
    /// This must be a pure function: given the same state and event,
    /// it must produce the same result. No side effects.
    fn apply(&self, state: &mut Self::State, event: &Self::Event);

    /// Convert aggregate call results into input for the next iteration (saga only)
    ///
    /// Aggregates use `Infallible` for `CallResult`, so this is never called.
    /// The default implementation panics—sagas must override this.
    fn feedback_input(_results: Vec<Self::CallResult>) -> Self::Input {
        unreachable!("Aggregates don't use Continue, so feedback_input is never called")
    }

    /// Event type name for serialization (e.g., "EventCreated", "OrderPlaced")
    ///
    /// Used by the infrastructure to tag serialized events for deserialization.
    fn event_type_name(event: &Self::Event) -> &'static str;
}

// ═══════════════════════════════════════════════════════════════════
// GENERATED: Business Logic Implementation (pure logic)
// ═══════════════════════════════════════════════════════════════════

use std::convert::Infallible;

pub struct EventBusinessLogic;

/// For aggregates:
/// - `Input` is just the Command type (no feedback needed)
/// - `Call` and `CallResult` are `Infallible` (aggregates never call other aggregates)
impl BusinessLogic for EventBusinessLogic {
    type State = EventState;
    type Input = EventCommand;
    type Event = EventEvent;
    type Error = EventError;
    type Call = Infallible;        // Aggregates never make calls
    type CallResult = Infallible;  // Aggregates never receive call results

    fn stream_id(input: &EventCommand) -> StreamId {
        match input {
            EventCommand::Create { event_id, .. } |
            EventCommand::Update { event_id, .. } |
            EventCommand::Publish { event_id } |
            EventCommand::Cancel { event_id, .. } => {
                StreamId::new(format!("event-{}", event_id))
            }
        }
    }

    /// Process a command against current state
    ///
    /// Aggregates ALWAYS return `Ok(Done(events))` or `Err(error)`.
    /// They never return `Continue` because they never call other aggregates.
    fn process(
        &self,
        state: &EventState,
        command: EventCommand,
        clock: &dyn Clock,
    ) -> Result<BusinessResult<EventEvent, Infallible>, EventError> {
        match command {
            EventCommand::Create { event_id, name, owner_id, venue, date, pricing_tiers } => {
                // Validation: all business rules checked upfront
                if state.event_id.is_some() {
                    return Err(EventError::AlreadyExists);
                }
                if name.is_empty() {
                    return Err(EventError::ValidationFailed {
                        message: "Event name cannot be empty".into()
                    });
                }
                if venue.sections.is_empty() {
                    return Err(EventError::ValidationFailed {
                        message: "Venue must have at least one section".into()
                    });
                }

                // Success: emit event and finish
                Ok(BusinessResult::Done(vec![EventEvent::Created {
                    event_id,
                    name,
                    owner_id,
                    venue,
                    date,
                    pricing_tiers,
                    created_at: clock.now(),
                }]))
            }

            EventCommand::Publish { event_id } => {
                if state.event_id.is_none() {
                    return Err(EventError::NotFound);
                }
                if state.status != EventStatus::Draft {
                    return Err(EventError::InvalidStateTransition {
                        from: state.status,
                        to: EventStatus::Published,
                    });
                }

                Ok(BusinessResult::Done(vec![EventEvent::Published {
                    event_id,
                    published_at: clock.now(),
                }]))
            }

            EventCommand::Cancel { event_id, reason } => {
                if state.event_id.is_none() {
                    return Err(EventError::NotFound);
                }
                if state.status == EventStatus::Cancelled {
                    return Err(EventError::InvalidStateTransition {
                        from: state.status,
                        to: EventStatus::Cancelled,
                    });
                }

                Ok(BusinessResult::Done(vec![EventEvent::Cancelled {
                    event_id,
                    reason,
                    cancelled_at: clock.now(),
                }]))
            }

            EventCommand::Update { event_id, name, venue, date } => {
                if state.event_id.is_none() {
                    return Err(EventError::NotFound);
                }
                if state.status != EventStatus::Draft {
                    return Err(EventError::InvalidStateTransition {
                        from: state.status,
                        to: state.status, // Can't update non-draft
                    });
                }

                Ok(BusinessResult::Done(vec![EventEvent::Updated {
                    event_id,
                    changes: EventChanges { name, venue, date },
                    updated_at: clock.now(),
                }]))
            }
        }
    }

    fn apply(&self, state: &mut EventState, event: &EventEvent) {
        match event {
            EventEvent::Created { event_id, name, owner_id, venue, date, pricing_tiers, .. } => {
                state.event_id = Some(*event_id);
                state.name = name.clone();
                state.owner_id = Some(*owner_id);
                state.venue = Some(venue.clone());
                state.date = Some(*date);
                state.pricing_tiers = pricing_tiers.clone();
                state.status = EventStatus::Draft;
            }
            EventEvent::Updated { changes, .. } => {
                if let Some(ref name) = changes.name {
                    state.name = name.clone();
                }
                if let Some(ref venue) = changes.venue {
                    state.venue = Some(venue.clone());
                }
                if let Some(ref date) = changes.date {
                    state.date = Some(*date);
                }
            }
            EventEvent::Published { .. } => {
                state.status = EventStatus::Published;
            }
            EventEvent::Cancelled { .. } => {
                state.status = EventStatus::Cancelled;
            }
        }
    }

    fn event_type_name(event: &EventEvent) -> &'static str {
        match event {
            EventEvent::Created { .. } => "EventCreated",
            EventEvent::Updated { .. } => "EventUpdated",
            EventEvent::Published { .. } => "EventPublished",
            EventEvent::Cancelled { .. } => "EventCancelled",
        }
    }

    // Note: feedback_input uses default impl (unreachable) since aggregates
    // never return Continue and thus never receive feedback.
}
```

### Infrastructure Handler

The infrastructure handler is **the same for aggregates and sagas**. For aggregates, the loop exits on the first iteration because they always return `BusinessResult::Done`.

```rust
// ═══════════════════════════════════════════════════════════════════
// FRAMEWORK: Unified Handler (same for aggregates and sagas)
// ═══════════════════════════════════════════════════════════════════

/// Result of handling a command
#[derive(Debug, Clone)]
pub struct HandleResult {
    /// New version after persisting events
    pub version: Version,
}

/// Errors that can occur during handling
#[derive(Debug, thiserror::Error)]
pub enum HandlerError<E: std::error::Error> {
    #[error("business logic error: {0}")]
    Business(E),

    #[error("failed to load events: {0}")]
    Load(EventStoreError),

    #[error("failed to persist events: {0}")]
    Persist(EventStoreError),

    #[error("failed to broadcast events: {0}")]
    Broadcast(EventBusError),

    #[error("serialization error: {0}")]
    Serialization(SerializationError),
}

/// The unified handler for aggregates and sagas.
///
/// For aggregates, `CallExecutor` is typically `NoOpCallExecutor` (never used).
/// For sagas, `CallExecutor` dispatches calls to the appropriate aggregate handlers.
pub struct Handler<T: BusinessLogic, E: CallExecutor<T::Call, T::CallResult>> {
    business: T,
    event_store: Arc<dyn EventStore>,
    event_bus: Arc<dyn EventBus>,
    clock: Arc<dyn Clock>,
    call_executor: E,
    topic: String,
}

/// Trait for executing aggregate calls (saga only)
pub trait CallExecutor<C, R>: Send + Sync {
    /// Execute a batch of calls and return results
    ///
    /// Implementations may execute calls in parallel or sequentially.
    fn execute(&self, calls: Vec<C>) -> impl Future<Output = Vec<R>> + Send;
}

/// No-op executor for aggregates (which never make calls)
pub struct NoOpCallExecutor;

impl CallExecutor<Infallible, Infallible> for NoOpCallExecutor {
    async fn execute(&self, _calls: Vec<Infallible>) -> Vec<Infallible> {
        // Infallible means this is never called
        vec![]
    }
}

impl<T, E> Handler<T, E>
where
    T: BusinessLogic,
    E: CallExecutor<T::Call, T::CallResult>,
{
    /// Create a new handler
    pub fn new(
        business: T,
        event_store: Arc<dyn EventStore>,
        event_bus: Arc<dyn EventBus>,
        clock: Arc<dyn Clock>,
        call_executor: E,
        topic: String,
    ) -> Self {
        Self { business, event_store, event_bus, clock, call_executor, topic }
    }

    /// Handle input end-to-end
    ///
    /// This unified loop works for both aggregates and sagas:
    /// - Aggregates always return Done on first iteration
    /// - Sagas may return Continue multiple times before Done
    pub async fn handle(&self, input: T::Input) -> Result<HandleResult, HandlerError<T::Error>> {
        let stream_id = T::stream_id(&input);
        let (mut state, mut version) = self.load_state(&stream_id).await?;
        let mut current_input = input;

        loop {
            let result = self.business
                .process(&state, current_input, self.clock.as_ref())
                .map_err(HandlerError::Business)?;

            match result {
                BusinessResult::Done(events) => {
                    if !events.is_empty() {
                        version = self.persist_events(&stream_id, &events, version).await?;
                        self.apply_all(&mut state, &events);
                        self.broadcast(&events).await?;
                    }
                    return Ok(HandleResult { version });
                }

                BusinessResult::Continue { events, calls } => {
                    if !events.is_empty() {
                        version = self.persist_events(&stream_id, &events, version).await?;
                        self.apply_all(&mut state, &events);
                        self.broadcast(&events).await?;
                    }

                    // Execute aggregate calls and feed results back
                    let feedback = self.call_executor.execute(calls).await;
                    current_input = T::feedback_input(feedback);
                    // Loop continues with feedback...
                }
            }
        }
    }

    /// Load state by replaying events
    async fn load_state(&self, stream_id: &StreamId) -> Result<(T::State, Version), HandlerError<T::Error>> {
        let raw_events = self.event_store
            .load(stream_id, None)
            .await
            .map_err(HandlerError::Load)?;

        let mut state = T::State::default();
        let mut version = Version::initial();

        for raw in raw_events {
            let event: T::Event = self.deserialize_event(&raw)?;
            self.business.apply(&mut state, &event);
            version = raw.version;
        }

        Ok((state, version))
    }

    /// Persist events to the event store with optimistic concurrency
    async fn persist_events(
        &self,
        stream_id: &StreamId,
        events: &[T::Event],
        expected_version: Version,
    ) -> Result<Version, HandlerError<T::Error>> {
        let serialized: Vec<SerializedEvent> = events
            .iter()
            .map(|e| self.serialize_event(e))
            .collect::<Result<_, _>>()?;

        self.event_store
            .append(stream_id, Some(expected_version), serialized)
            .await
            .map_err(HandlerError::Persist)
    }

    /// Broadcast events to the event bus for projections and other subscribers
    async fn broadcast(&self, events: &[T::Event]) -> Result<(), HandlerError<T::Error>> {
        for event in events {
            let serialized = self.serialize_event(event)?;
            self.event_bus
                .publish(&self.topic, serialized)
                .await
                .map_err(HandlerError::Broadcast)?;
        }
        Ok(())
    }

    /// Apply events to state (for state reconstruction)
    fn apply_all(&self, state: &mut T::State, events: &[T::Event]) {
        for event in events {
            self.business.apply(state, event);
        }
    }

    /// Serialize an event for persistence/broadcast
    fn serialize_event(&self, event: &T::Event) -> Result<SerializedEvent, HandlerError<T::Error>> {
        let type_name = T::event_type_name(event);
        let payload = bincode::serialize(event)
            .map_err(|e| HandlerError::Serialization(SerializationError::Encode(e.to_string())))?;

        Ok(SerializedEvent {
            event_type: type_name.to_string(),
            payload,
            metadata: None,
        })
    }

    /// Deserialize an event from storage
    fn deserialize_event(&self, raw: &SerializedEvent) -> Result<T::Event, HandlerError<T::Error>> {
        bincode::deserialize(&raw.payload)
            .map_err(|e| HandlerError::Serialization(SerializationError::Decode(e.to_string())))
    }
}
```

## Saga Implementation

Sagas use the **same `BusinessLogic` trait and `Handler`** as aggregates. The only difference:
- Aggregates always return `BusinessResult::Done`
- Sagas return `BusinessResult::Continue` when calling other aggregates, and `BusinessResult::Done` when finished

### Industrial-Grade Compensation

Compensation is **critical** for production sagas. When a saga fails partway through, previously completed steps must be rolled back. This section demonstrates a complete compensation pattern.

#### Compensation Philosophy

1. **Every forward action has a compensation action**: If you create an event, you must be able to cancel it
2. **Compensation is recorded in saga state**: Track what needs to be rolled back
3. **Compensation is idempotent**: Running compensation twice has the same effect as once
4. **Compensation failures are logged and retried**: The system must eventually reach a consistent state
5. **Compensation order is reverse of execution**: Last completed step is compensated first

### Saga Business Logic with Compensation

```rust
// ═══════════════════════════════════════════════════════════════════
// GENERATED: Saga with industrial-grade compensation
// ═══════════════════════════════════════════════════════════════════

pub struct EventInventorySagaLogic;

impl BusinessLogic for EventInventorySagaLogic {
    type State = SagaState;
    type Input = SagaInput;
    type Event = SagaEvent;
    type Error = SagaError;
    type Call = SagaCall;
    type CallResult = SagaCallResult;

    fn stream_id(input: &SagaInput) -> StreamId {
        match input {
            SagaInput::Command(SagaCommand::CreateEventWithInventory { saga_id, .. }) => {
                StreamId::new(format!("saga-event-inventory-{}", saga_id))
            }
            SagaInput::Feedback(_) => {
                // Feedback is processed in the same handler loop as the command,
                // so stream_id is already known. This branch should never be called
                // directly—the handler caches the stream_id from the initial command.
                unreachable!("stream_id called on Feedback input")
            }
        }
    }

    fn process(
        &self,
        state: &SagaState,
        input: SagaInput,
        clock: &dyn Clock,
    ) -> Result<BusinessResult<SagaEvent, SagaCall>, SagaError> {
        match (&state.phase, input) {
            // ════════════════════════════════════════════════════════════════
            // PHASE: Initial → CreatingEvent
            // ════════════════════════════════════════════════════════════════
            (SagaPhase::Initial, SagaInput::Command(cmd)) => {
                let SagaCommand::CreateEventWithInventory {
                    saga_id, event_id, name, owner_id, venue, date, pricing_tiers
                } = cmd;

                // Validation (fail fast, before any side effects)
                if name.is_empty() {
                    return Err(SagaError::ValidationFailed("Event name required".into()));
                }
                if venue.sections.is_empty() {
                    return Err(SagaError::ValidationFailed("Venue must have sections".into()));
                }

                let sections: Vec<SectionSpec> = venue.sections.iter()
                    .map(|s| SectionSpec {
                        name: s.name.clone(),
                        capacity: s.capacity,
                    })
                    .collect();

                Ok(BusinessResult::Continue {
                    events: vec![SagaEvent::Initiated {
                        saga_id,
                        event_id,
                        sections: sections.clone(),
                        initiated_at: clock.now(),
                    }],
                    calls: vec![SagaCall::CreateEvent {
                        event_id,
                        name,
                        owner_id,
                        venue,
                        date,
                        pricing_tiers,
                    }],
                })
            }

            // ════════════════════════════════════════════════════════════════
            // PHASE: CreatingEvent → InitializingInventory (success)
            //                      → CompensationCompleted (failure, nothing to compensate)
            // ════════════════════════════════════════════════════════════════
            (SagaPhase::CreatingEvent, SagaInput::Feedback(results)) => {
                let result = results.into_iter().next()
                    .ok_or(SagaError::InvalidStateTransition {
                        from: state.phase,
                        input_type: "empty feedback",
                    })?;

                match result {
                    SagaCallResult::EventCreated { event_id } => {
                        // Success! Now initialize all inventory sections in parallel
                        let calls: Vec<SagaCall> = state.sections_to_initialize.iter()
                            .map(|spec| SagaCall::InitializeInventory {
                                event_id,
                                section: spec.name.clone(),
                                capacity: spec.capacity,
                            })
                            .collect();

                        Ok(BusinessResult::Continue {
                            events: vec![SagaEvent::EventCreated {
                                event_id,
                                created_at: clock.now(),
                            }],
                            calls,
                        })
                    }

                    SagaCallResult::EventFailed { error } => {
                        // Event creation failed. Nothing to compensate yet.
                        let event_id = state.event_id.unwrap_or_else(EventId::new);
                        Ok(BusinessResult::Done(vec![
                            SagaEvent::CompensationStarted {
                                reason: error.clone(),
                                started_at: clock.now(),
                            },
                            SagaEvent::CompensationCompleted {
                                event_id,
                                sections_compensated: 0,
                                completed_at: clock.now(),
                            },
                        ]))
                    }

                    _ => Err(SagaError::InvalidStateTransition {
                        from: state.phase,
                        input_type: "unexpected result type",
                    }),
                }
            }

            // ════════════════════════════════════════════════════════════════
            // PHASE: InitializingInventory → Completed (all success)
            //                              → CompensatingInventory (any failure)
            // ════════════════════════════════════════════════════════════════
            (SagaPhase::InitializingInventory, SagaInput::Feedback(results)) => {
                let event_id = state.event_id.expect("event_id must be set in InitializingInventory phase");

                let mut events = Vec::new();
                let mut newly_initialized = Vec::new();
                let mut failure: Option<String> = None;

                for result in results {
                    match result {
                        SagaCallResult::InventoryInitialized { section, .. } => {
                            events.push(SagaEvent::SectionInitialized {
                                event_id,
                                section: section.clone(),
                                initialized_at: clock.now(),
                            });
                            newly_initialized.push(section);
                        }
                        SagaCallResult::InventoryFailed { section, error } => {
                            failure = Some(format!("Section '{}' failed: {}", section, error));
                        }
                        _ => {}
                    }
                }

                if let Some(error) = failure {
                    // FAILURE: Some inventory initialization failed.
                    // We must compensate all successfully initialized sections.
                    let sections_to_compensate: Vec<String> = state.sections_initialized
                        .iter()
                        .chain(newly_initialized.iter())
                        .cloned()
                        .collect();

                    events.push(SagaEvent::CompensationStarted {
                        reason: error,
                        started_at: clock.now(),
                    });

                    if sections_to_compensate.is_empty() {
                        // No inventory to compensate, go straight to compensating event
                        Ok(BusinessResult::Continue {
                            events,
                            calls: vec![SagaCall::CancelEvent {
                                event_id,
                                reason: "Saga compensation: inventory initialization failed".into(),
                            }],
                        })
                    } else {
                        // Compensate inventory first
                        let calls: Vec<SagaCall> = sections_to_compensate.iter()
                            .map(|section| SagaCall::ReleaseInventory {
                                event_id,
                                section: section.clone(),
                            })
                            .collect();

                        Ok(BusinessResult::Continue { events, calls })
                    }
                } else {
                    // SUCCESS: All inventory sections initialized.
                    // Check if we're done (all sections processed).
                    let total_initialized = state.sections_initialized.len() + newly_initialized.len();
                    let total_expected = state.sections_to_initialize.len();

                    if total_initialized >= total_expected {
                        events.push(SagaEvent::Completed {
                            event_id,
                            sections_initialized: total_initialized as u32,
                            completed_at: clock.now(),
                        });
                        Ok(BusinessResult::Done(events))
                    } else {
                        // More sections to initialize (shouldn't happen with parallel calls,
                        // but supports sequential initialization if needed)
                        let remaining: Vec<SagaCall> = state.sections_to_initialize.iter()
                            .filter(|spec| !state.sections_initialized.contains(&spec.name)
                                        && !newly_initialized.contains(&spec.name))
                            .map(|spec| SagaCall::InitializeInventory {
                                event_id,
                                section: spec.name.clone(),
                                capacity: spec.capacity,
                            })
                            .collect();

                        Ok(BusinessResult::Continue { events, calls: remaining })
                    }
                }
            }

            // ════════════════════════════════════════════════════════════════
            // PHASE: CompensatingInventory → CompensatingEvent (all compensated)
            // ════════════════════════════════════════════════════════════════
            (SagaPhase::CompensatingInventory, SagaInput::Feedback(results)) => {
                let event_id = state.event_id.expect("event_id must be set");
                let mut events = Vec::new();
                let mut compensation_failures = Vec::new();

                for result in results {
                    match result {
                        SagaCallResult::InventoryReleased { section, .. } => {
                            events.push(SagaEvent::SectionCompensated {
                                event_id,
                                section,
                                compensated_at: clock.now(),
                            });
                        }
                        SagaCallResult::InventoryReleaseFailed { section, error } => {
                            // Log but continue—we must try to compensate everything
                            compensation_failures.push(format!("{}: {}", section, error));
                        }
                        _ => {}
                    }
                }

                // Even if some compensations failed, proceed to compensate the event.
                // The event cancellation might still succeed, leaving the system
                // in a recoverable state.
                Ok(BusinessResult::Continue {
                    events,
                    calls: vec![SagaCall::CancelEvent {
                        event_id,
                        reason: format!(
                            "Saga compensation. Inventory failures: {:?}",
                            compensation_failures
                        ),
                    }],
                })
            }

            // ════════════════════════════════════════════════════════════════
            // PHASE: CompensatingEvent → CompensationCompleted (success)
            //                          → Failed (compensation failed)
            // ════════════════════════════════════════════════════════════════
            (SagaPhase::CompensatingEvent, SagaInput::Feedback(results)) => {
                let event_id = state.event_id.expect("event_id must be set");

                let result = results.into_iter().next()
                    .ok_or(SagaError::InvalidStateTransition {
                        from: state.phase,
                        input_type: "empty feedback",
                    })?;

                match result {
                    SagaCallResult::EventCancelled { .. } => {
                        let sections_compensated = state.sections_to_compensate.len() as u32;
                        Ok(BusinessResult::Done(vec![
                            SagaEvent::EventCompensated {
                                event_id,
                                compensated_at: clock.now(),
                            },
                            SagaEvent::CompensationCompleted {
                                event_id,
                                sections_compensated,
                                completed_at: clock.now(),
                            },
                        ]))
                    }

                    SagaCallResult::EventCancelFailed { error, .. } => {
                        // Compensation itself failed. This is a serious error that
                        // requires manual intervention or retry from an external system.
                        Ok(BusinessResult::Done(vec![SagaEvent::Failed {
                            event_id,
                            error: format!("Compensation failed: {}", error),
                            compensation_attempted: true,
                            failed_at: clock.now(),
                        }]))
                    }

                    _ => Err(SagaError::InvalidStateTransition {
                        from: state.phase,
                        input_type: "unexpected result type",
                    }),
                }
            }

            // ════════════════════════════════════════════════════════════════
            // Terminal states: no further processing
            // ════════════════════════════════════════════════════════════════
            (phase, input) if phase.is_terminal() => {
                Err(SagaError::InvalidStateTransition {
                    from: *phase,
                    input_type: match input {
                        SagaInput::Command(_) => "command",
                        SagaInput::Feedback(_) => "feedback",
                    },
                })
            }

            // Catch-all for unexpected state/input combinations
            (phase, input) => {
                Err(SagaError::InvalidStateTransition {
                    from: *phase,
                    input_type: match input {
                        SagaInput::Command(_) => "command",
                        SagaInput::Feedback(_) => "feedback",
                    },
                })
            }
        }
    }

    fn apply(&self, state: &mut SagaState, event: &SagaEvent) {
        match event {
            // Forward flow
            SagaEvent::Initiated { saga_id, event_id, sections, .. } => {
                state.saga_id = Some(*saga_id);
                state.event_id = Some(*event_id);
                state.sections_to_initialize = sections.clone();
                state.phase = SagaPhase::CreatingEvent;
            }
            SagaEvent::EventCreated { .. } => {
                state.event_needs_compensation = true;
                state.phase = SagaPhase::InitializingInventory;
            }
            SagaEvent::SectionInitialized { section, .. } => {
                state.sections_initialized.insert(section.clone());
                // Phase stays InitializingInventory until all done
            }
            SagaEvent::Completed { .. } => {
                state.phase = SagaPhase::Completed;
            }

            // Compensation flow
            SagaEvent::CompensationStarted { reason, .. } => {
                state.compensation_reason = Some(reason.clone());
                // Copy initialized sections to compensation tracking
                state.sections_to_compensate = state.sections_initialized.clone();
                if state.sections_to_compensate.is_empty() {
                    state.phase = SagaPhase::CompensatingEvent;
                } else {
                    state.phase = SagaPhase::CompensatingInventory;
                }
            }
            SagaEvent::SectionCompensated { section, .. } => {
                state.sections_to_compensate.remove(section);
                if state.sections_to_compensate.is_empty() {
                    state.phase = SagaPhase::CompensatingEvent;
                }
            }
            SagaEvent::EventCompensated { .. } => {
                state.event_needs_compensation = false;
                // Phase transition happens with CompensationCompleted
            }
            SagaEvent::CompensationCompleted { .. } => {
                state.phase = SagaPhase::CompensationCompleted;
            }

            // Terminal failure
            SagaEvent::Failed { .. } => {
                state.phase = SagaPhase::Failed;
            }
        }
    }

    fn feedback_input(results: Vec<SagaCallResult>) -> SagaInput {
        SagaInput::Feedback(results)
    }

    fn event_type_name(event: &SagaEvent) -> &'static str {
        match event {
            SagaEvent::Initiated { .. } => "SagaInitiated",
            SagaEvent::EventCreated { .. } => "SagaEventCreated",
            SagaEvent::SectionInitialized { .. } => "SagaSectionInitialized",
            SagaEvent::Completed { .. } => "SagaCompleted",
            SagaEvent::CompensationStarted { .. } => "SagaCompensationStarted",
            SagaEvent::SectionCompensated { .. } => "SagaSectionCompensated",
            SagaEvent::EventCompensated { .. } => "SagaEventCompensated",
            SagaEvent::CompensationCompleted { .. } => "SagaCompensationCompleted",
            SagaEvent::Failed { .. } => "SagaFailed",
        }
    }
}
```

### Saga Call Executor

The saga needs a `CallExecutor` that dispatches calls to the appropriate aggregate handlers:

```rust
/// Executor that dispatches saga calls to aggregate handlers
pub struct SagaCallExecutor {
    event_handler: Arc<Handler<EventBusinessLogic, NoOpCallExecutor>>,
    inventory_handler: Arc<Handler<InventoryBusinessLogic, NoOpCallExecutor>>,
}

impl CallExecutor<SagaCall, SagaCallResult> for SagaCallExecutor {
    async fn execute(&self, calls: Vec<SagaCall>) -> Vec<SagaCallResult> {
        // Execute all calls in parallel for maximum throughput
        let futures: Vec<_> = calls.into_iter()
            .map(|call| self.execute_single(call))
            .collect();

        futures::future::join_all(futures).await
    }
}

impl SagaCallExecutor {
    async fn execute_single(&self, call: SagaCall) -> SagaCallResult {
        match call {
            SagaCall::CreateEvent { event_id, name, owner_id, venue, date, pricing_tiers } => {
                let cmd = EventCommand::Create { event_id, name, owner_id, venue, date, pricing_tiers };
                match self.event_handler.handle(cmd).await {
                    Ok(_) => SagaCallResult::EventCreated { event_id },
                    Err(e) => SagaCallResult::EventFailed { error: e.to_string() },
                }
            }

            SagaCall::InitializeInventory { event_id, section, capacity } => {
                let cmd = InventoryCommand::Initialize { event_id, section: section.clone(), capacity };
                match self.inventory_handler.handle(cmd).await {
                    Ok(_) => SagaCallResult::InventoryInitialized { event_id, section },
                    Err(e) => SagaCallResult::InventoryFailed { section, error: e.to_string() },
                }
            }

            SagaCall::CancelEvent { event_id, reason } => {
                let cmd = EventCommand::Cancel { event_id, reason };
                match self.event_handler.handle(cmd).await {
                    Ok(_) => SagaCallResult::EventCancelled { event_id },
                    Err(e) => SagaCallResult::EventCancelFailed { event_id, error: e.to_string() },
                }
            }

            SagaCall::ReleaseInventory { event_id, section } => {
                let cmd = InventoryCommand::Release { event_id, section: section.clone() };
                match self.inventory_handler.handle(cmd).await {
                    Ok(_) => SagaCallResult::InventoryReleased { event_id, section },
                    Err(e) => SagaCallResult::InventoryReleaseFailed { section, error: e.to_string() },
                }
            }
        }
    }
}
```

### Compensation Flow Diagram

```
                                    ┌─────────────────┐
                                    │     Initial     │
                                    └────────┬────────┘
                                             │ Command

                                    │  CreatingEvent  │
```

### Saga Schema

```yaml
# event_inventory_saga.yaml

  - Event
  - Inventory

state:
  fields:
    - event_id: Option<EventId>
    - pending_sections: HashSet<String>
    - section_capacities: HashMap<String, Capacity>
    - phase: SagaPhase = Initial

command:
  CreateEventWithInventory:
    fields:
      - event_id: EventId
      - name: String
      - owner_id: UserId
      - venue: Venue
      - date: EventDate
      - pricing_tiers: Vec<PricingTier>
    validation:
      - not(name.is_empty()): "Event name required"
      - not(venue.sections.is_empty()): "Venue must have sections"

# Phase definitions (state machine)
phases:
  Initial:
    on: command(CreateEventWithInventory)
    emit: Initiated
    call:
      aggregate: Event
      command: Create
      with:
        event_id: command.event_id
        name: command.name
        owner_id: command.owner_id
        venue: command.venue
        date: command.date
        pricing_tiers: command.pricing_tiers
    on_success: transition(WaitingForEvent)
    on_failure: emit(Failed)

  WaitingForEvent:
    on: aggregate_success(Event)
    emit: EventCreated
    call_parallel:
      for_each: state.pending_sections
      aggregate: Inventory
      command: Initialize
      with:
        event_id: state.event_id
        section: item
        capacity: state.section_capacities[item]
    on_each_success: emit(SectionInitialized)
    on_any_failure: emit(Failed)
    transition: WaitingForInventory

  # Note: `when` conditions are evaluated BEFORE applying the emitted event.
  # So `len() == 1` means "this is the last pending section".
  WaitingForInventory:
    on: aggregate_success(Inventory)
    when: state.pending_sections.len() == 1  # Last one remaining
    emit: Completed
    transition: Done

  WaitingForInventory:
    on: aggregate_success(Inventory)
    when: state.pending_sections.len() > 1  # More remaining after this one
    emit: SectionInitialized
    # Stay in same phase (implicit)

# Events
events:
  Initiated:
    fields: [event_id, sections: Vec<String>, initiated_at]
    applies:
      - state.event_id = Some(event_id)
      - state.pending_sections = sections.into_iter().collect()
      - state.phase = WaitingForEvent

  EventCreated:
    fields: [event_id, sections: Vec<String>, created_at]
    applies:
      - state.phase = WaitingForInventory

  SectionInitialized:
    fields: [event_id, section, initialized_at]
    applies:
      - state.pending_sections.remove(&section)

  Completed:
    fields: [event_id, sections_initialized: u32, completed_at]
    applies:
      - state.phase = Completed

  Failed:
    fields: [event_id, error: String, failed_at]
    applies:
      - state.phase = Failed
```

## Additional Design Considerations

### Crash Recovery

**Current Architecture**: When a process crashes, replaying events from the event store restores state. The reducer processes each persisted event, and the `apply_event` function reconstructs the state.

**Option A**: Similar approach, but cleaner:
1. Infrastructure handler calls `load_state()` which replays all persisted events
2. Business reducer's `apply()` function reconstructs state
3. Since only business events are persisted, replay is faster and the reconstructed state reflects only business decisions

For sagas, crash recovery requires special handling:
- On startup, scan for incomplete sagas (phase is not terminal: `Completed`, `CompensationCompleted`, or `Failed`)
- Resume from last persisted event
- Re-execute pending aggregate calls based on current phase

```rust
/// Saga recovery service - runs on startup
pub struct SagaRecoveryService<T: BusinessLogic, E: CallExecutor<T::Call, T::CallResult>> {
    handler: Handler<T, E>,
    event_store: Arc<dyn EventStore>,
}

impl<T, E> SagaRecoveryService<T, E>
where
    T: BusinessLogic,
    E: CallExecutor<T::Call, T::CallResult>,
{
    async fn recover_incomplete_sagas(&self) -> Result<()> {
        let incomplete = self.find_incomplete_sagas().await?;
        for stream_id in incomplete {
            let (state, version) = self.load_state(&stream_id).await?;

            // Determine what calls to re-issue based on current phase
            if let Some(calls) = self.pending_calls_for_phase(&state) {
                let feedback = self.handler.call_executor.execute(calls).await;
                let input = T::feedback_input(feedback);
                self.handler.handle(input).await?;
            }
        }
        Ok(())
    }
}
```

### Idempotency

**Current Architecture**: Uses `respond_to: ResponseChannel` to track request-response correlation. Duplicate commands return the same response without re-processing.

**Option A**: Idempotency is handled at the infrastructure layer:

```rust
/// Wrapper that adds idempotency to any handler
pub struct IdempotentHandler<T: BusinessLogic, E: CallExecutor<T::Call, T::CallResult>> {
    inner: Handler<T, E>,
    cache: Arc<dyn IdempotencyCache>,
}

impl<T, E> IdempotentHandler<T, E>
where
    T: BusinessLogic,
    E: CallExecutor<T::Call, T::CallResult>,
{
    async fn handle(&self, input: T::Input) -> Result<HandleResult, HandlerError<T::Error>> {
        let key = self.derive_idempotency_key(&input);

        // 1. Check if we've already processed this
        if let Some(cached) = self.cache.get(&key).await? {
            return Ok(cached);
        }

        // 2. Process the input
        let result = self.inner.handle(input).await?;

        // 3. Cache the result for future duplicate requests
        self.cache.set(&key, &result).await?;

        Ok(result)
    }
}
```

The business logic doesn't need to know about idempotency—it's purely an infrastructure concern.

### Projections Integration

**Current Architecture**: `broadcast_on_success` in `append_events!` publishes events to the event bus after successful persistence. Projections subscribe to the event bus.

**Option A**: Same pattern, built into the unified `Handler`:

```rust
// Already in Handler::handle() - broadcast is automatic
async fn broadcast(&self, events: &[T::Event]) -> Result<(), HandlerError<T::Error>> {
    for event in events {
        let serialized = self.serialize_event(event)?;
        self.event_bus
            .publish(&self.topic, serialized)
            .await
            .map_err(HandlerError::Broadcast)?;
    }
    Ok(())
}
```

The key benefit: projections only receive business events (`EventCreated`, `OrderPlaced`), never infrastructure noise (`VersionUpdated`, `LoadFailed`).

### Request-Response Correlation

**Current Architecture**: `respond_to: ResponseChannel` carries through the action chain.

**Option A**: The infrastructure handler owns the response lifecycle directly:

```rust
// HTTP handler (e.g., Axum)
async fn create_event(
    State(handler): State<Arc<Handler<EventBusinessLogic, NoOpCallExecutor>>>,
    Json(cmd): Json<CreateEventRequest>,
) -> Result<Json<CreateEventResponse>, ApiError> {
    let event_id = EventId::new();
    let command = EventCommand::Create {
        event_id,
        name: cmd.name,
        owner_id: cmd.owner_id,
        venue: cmd.venue,
        date: cmd.date,
        pricing_tiers: cmd.pricing_tiers,
    };

    let result = handler.handle(command).await?;

    Ok(Json(CreateEventResponse {
        event_id,
        version: result.version,
    }))
}
```

The business logic never sees `respond_to`. It just returns `Result<BusinessResult<...>, ...>`. The HTTP handler (or gRPC, WebSocket, etc.) decides how to communicate the result.

✅ Clean event store is important (audit log, compliance)
✅ Compiler simplicity matters (less closure generation)
✅ Debugging production issues is a priority
✅ You want infrastructure to be invisible/templated

✅ "It works" is sufficient
✅ No immediate need for cleaner event store
✅ Compiler is already handling current pattern well
✅ Don't want to invest 4-6 weeks in refactoring
✅ Debugging current code is acceptable

### Recommendation

**For a compilation target where users never see the Rust code**: Option A is better.

The investment pays off in:
- Simpler compiler (less closure generation)
- Cleaner event stores (pure business audit log)
- Easier debugging (when issues arise in production)
- Smaller generated code (500 vs 2,300 lines)

The current architecture is good for hand-written code where you want everything in one place. For generated code, separation of concerns wins.

## Appendix C: Serialization Details

### Event Serialization Format

Events are serialized using **bincode** for efficiency:

```rust
/// Serialized event structure stored in the event store
#[derive(Clone, Debug)]
pub struct SerializedEvent {
    /// Event type discriminator (e.g., "EventCreated", "OrderPlaced")
    pub event_type: String,

    /// Bincode-serialized event payload
    pub payload: Vec<u8>,

    /// Optional metadata (correlation ID, causation ID, user ID, etc.)
    pub metadata: Option<EventMetadata>,
}

#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct EventMetadata {
    pub correlation_id: Option<String>,
    pub causation_id: Option<String>,
    pub user_id: Option<String>,
    pub timestamp: DateTime<Utc>,
}
```

### Why Bincode?

| Format | Size | Speed | Schema Evolution |
|--------|------|-------|------------------|
| bincode | Smallest (~30% of JSON) | Fastest | Limited (add fields at end) |
| JSON | Largest | Slowest | Best (field names preserved) |
| MessagePack | Medium | Fast | Good |
| Protocol Buffers | Small | Fast | Best (with .proto files) |

For a compilation target where the compiler controls both serialization and deserialization, **bincode** is optimal:
- 5-10x faster than JSON
- 30-70% smaller payloads
- No schema files needed

### Schema Evolution Strategy

Since the YAML compiler generates both event types and serialization code, schema evolution is handled at compile time:

1. **Adding fields**: Add with `#[serde(default)]` for backward compatibility
2. **Removing fields**: Never remove—mark as deprecated and ignore
3. **Renaming fields**: Use `#[serde(rename = "old_name")]`
4. **Major changes**: Create new event type (e.g., `EventCreatedV2`)

```rust
#[derive(Serialize, Deserialize)]
pub enum EventEvent {
    // Original version
    Created { /* ... */ },

    // New version with additional fields
    #[serde(rename = "EventCreatedV2")]
    CreatedV2 {
        event_id: EventId,
        name: String,
        // New field with default
        #[serde(default)]
        category: Option<EventCategory>,
        // ...
    },
}
```
